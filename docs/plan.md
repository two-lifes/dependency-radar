# Dependency Radar — план MVP

Общая память между сессиями. Каждая задача = одна сессия; в конце `pnpm lint && pnpm typecheck && pnpm test` зелёные и есть что посмотреть или протестировать. Отмечать задачу только после подтверждения автора.

Правила продукта — в `spec.md` v1.3 и `screens.md` v2.2; здесь только решения по реализации, которых там нет.

## Принятые решения

- **Демо:** один общий демо-пользователь. Удаление проектов и аккаунта в демо заблокировано, ежедневная задача пересоздаёт сид.
- **Проверка:** выполняется внутри SSE route handler, каждый результат пакета сразу пишется в БД. При обрыве соединения проверка останавливается, а «Resume» / «Retry failed» доделывают только непроверенные пакеты. Если проверка 300 пакетов не укладывается в лимит функции Vercel (задача 2), проверка запускается отдельным запросом и пишет прогресс в БД, а SSE только читает его.
- **Release notes:** в MVP загружаются лениво при открытии карточки пакета, с кэшем. Сама проверка использует только npm и OSV.
- **Lock-файлы:** парсится только `package-lock.json` (v2/v3), из Upload и из GitHub-репозитория. Без него берётся максимальная версия, подходящая под диапазон.
- **Ежедневная задача:** workflow GitHub Actions по расписанию вызывает `/api/cron/daily` с секретом (decisions 11).
- **Ссылки подвала** (GitHub-репозиторий, портфолио): плейсхолдеры с пометкой `TODO`, автор даст URL позже.

## Допущения (можно поправить)

1. Unit-тесты не трогают БД. В CI Postgres поднимается service-контейнером.
2. В e2e внешние API подменяются MSW на стороне Node при `MOCK_EXTERNAL=1`.
